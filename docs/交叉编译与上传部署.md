# 交叉编译镜像并上传到云服务器（操作手册）

> 目标：在 **Mac(arm64)** 上构建出 **服务器需要的 amd64 镜像**，打包上传到京东云 ECS 运行；**全程不影响本地开发**。
> 适用镜像：`mall-admin`（后端）、`mall-frontend`（前端 nginx）。

---

## 为什么不影响本地运行

- 交叉编译产出的是**专供服务器的 amd64 镜像**，打的是独立 tag（`mall-admin:1.0` / `mall-frontend:1.0`），只会被导出成 tar 传走，**不参与本地开发**。
- 本地开发照旧：前端 `pnpm dev`、后端 `mvn spring-boot:run` 或原有的 `docker compose up -d`（dev 中间件），这些都**不动、不受影响**。
- buildx 用独立 builder 实例构建，不会污染你本地默认的 docker 镜像/容器。
- 唯一的本地产物是一个 tar 文件（`mall-images.tar.gz`），传完可随手删除。

---

## 前置条件（本机，一次性）

> 本机 Docker 运行时是 **Colima**（非 Docker Desktop）。Colima 的 docker CLI **不自带 buildx 插件**，需先手动安装，否则会报 `docker: unknown command: docker buildx`。

```bash
# 1. 安装 buildx 插件（Colima 不自带；直接放到 docker 的 cli-plugins 目录）
#    host 是 Apple Silicon，取 darwin-arm64；版本可换成最新 release
mkdir -p ~/.docker/cli-plugins
curl -fSL https://github.com/docker/buildx/releases/download/v0.19.3/buildx-v0.19.3.darwin-arm64 \
  -o ~/.docker/cli-plugins/docker-buildx
chmod +x ~/.docker/cli-plugins/docker-buildx
docker buildx version        # 应输出 github.com/docker/buildx v0.19.3

# 2. 注册 QEMU binfmt（让 arm64 主机能构建/模拟 amd64；只需一次）
docker run --privileged --rm tonistiigi/binfmt --install amd64

# 3. 创建支持跨架构的 builder（docker-container 驱动，默认 docker 驱动不支持跨平台）
docker buildx create --name mallbuilder --driver docker-container --use \
  || docker buildx use mallbuilder
docker buildx inspect --bootstrap   # 首次会拉取 moby/buildkit，网慢时耗时较久
```

>说明：
> - `--use` 只是把当前 buildx 上下文切到 mallbuilder，**不影响** `docker run` / `docker compose` 等日常命令。
> - 用 `docker-container` 驱动是跨架构构建的关键；默认的 `docker` 驱动无法构建与主机不同的架构。

---

## 步骤一：交叉编译 amd64 镜像（本机执行）

在项目根目录 `/Users/litian.phil/phil/java/mall` 下执行：

```bash
# 后端：强制构建 linux/amd64，并载入本地
docker buildx build --platform linux/amd64 \
  -f Backend/Dockerfile \
  -t mall-admin:1.0 \
  --load Backend

# 前端：同样构建 amd64（构建上下文 frontend 内含 nginx.conf）
docker buildx build --platform linux/amd64 \
  -f frontend/Dockerfile \
  -t mall-frontend:1.0 \
  --load frontend
```

要点：`--platform linux/amd64` 是关键——不加会构建成 Mac 的 arm64，传到服务器会报 `exec format error`。

---

## 步骤一补：拉取基础镜像的 amd64 版本（本机执行）

redis / minio 两个基础镜像也要打进压缩包，一起传到服务器（服务器完全离线，不联网拉任何镜像）。

> MySQL 不打包——本方案复用服务器上已有的 MySQL（`111.228.13.106:3306`），不再用容器化 MySQL。

**关键**：必须显式加 `--platform linux/amd64`，否则在 Mac 上会拉成 arm64 版本，传到服务器同样报 `exec format error`。

```bash
docker pull --platform linux/amd64 redis:7-alpine
docker pull --platform linux/amd64 minio/minio:latest
```

> 这两个镜像的 tag 与 `Backend/docker-compose.prod.yml` 里的完全一致，必须一字不差，否则服务器 `up` 时又会去联网拉。

---

## 步骤二：校验架构（关键，防不兼容）

```bash
docker image inspect mall-admin:1.0        --format '{{.Architecture}}'
docker image inspect mall-frontend:1.0     --format '{{.Architecture}}'
docker image inspect redis:7-alpine        --format '{{.Architecture}}'
docker image inspect minio/minio:latest    --format '{{.Architecture}}'
```

四行都必须输出 **`amd64`**。若出现 `arm64`，停下检查对应命令的 `--platform` 是否漏写，重新构建/拉取。

---

## 步骤三：导出并压缩为 tar（本机执行）

```bash
# 四个镜像一起导出并 gzip 压缩（3Mbps 带宽下必须压缩）
docker save \
  mall-admin:1.0 \
  mall-frontend:1.0 \
  redis:7-alpine \
  minio/minio:latest \
  | gzip > mall-images.tar.gz

# 看一下体积（一般 500MB~800MB）
ls -lh mall-images.tar.gz
```

---

## 步骤四：scp 上传到服务器（本机执行）

把下面的 `ECS_IP` 换成你的服务器公网 IP。

```bash
# 首次先在服务器建目录
ssh root@ECS_IP 'mkdir -p /opt/mall'

# 上传镜像包
scp mall-images.tar.gz root@ECS_IP:/opt/mall/

# 上传部署所需文件（首次部署需要；仅更新镜像时可跳过）
scp Backend/docker-compose.prod.yml root@ECS_IP:/opt/mall/
scp -r Backend/certs root@ECS_IP:/opt/mall/     # 你的 SSL 证书（server.crt / server.key）
scp Backend/.env     root@ECS_IP:/opt/mall/     # 你填好真实密码的 .env（不入 git）
# 注：复用现有 MySQL，通常无需传 sql；仅当现有 MySQL 里还没有 mall 库表时，
#     才需 scp -r Backend/sql 上去并手动导入（见步骤五补）。
```

---

## 步骤五：服务器加载并启动（在 ECS 上执行）

```bash
ssh root@ECS_IP
cd /opt/mall

# 载入镜像（一次性导入全部 4 个：mall-admin、mall-frontend、redis、minio）
gunzip -c mall-images.tar.gz | docker load

# 确认 4 个镜像都已在服务器本地
docker images | grep -E "mall-admin|mall-frontend|redis|minio"

# 启动（镜像都在本地，全程不联网拉取；后端会连服务器已有的 MySQL）
docker compose -f docker-compose.prod.yml up -d

# 查看状态
docker compose -f docker-compose.prod.yml ps
```

> 因为 4 个镜像已全部随包载入，服务器**无需配置镜像加速器、无需联网拉镜像**。

---

## 步骤五补：确认现有 MySQL 里有 mall 库表（在 ECS 上执行）

本方案复用服务器已有的 MySQL（`111.228.13.106`）。后端启动前先确认库表就绪：

```bash
# 用现有 MySQL 的 root 密码（即 .env 里的 DB_PASSWORD）
mysql -uroot -p -e "use mall; show tables;"
```

- 若已列出 31 张表（本地开发一直连的就是它，通常已存在），**无需任何操作**。
- 若库/表不存在，先建库并导入（需先按步骤四把 `Backend/sql` 传上来）：
  ```bash
  mysql -uroot -p -e "CREATE DATABASE IF NOT EXISTS mall DEFAULT CHARSET utf8mb4;"
  mysql -uroot -p mall < /opt/mall/sql/mall-admin.sql
  ```

---

## 步骤六：清理本机 tar（可选）

```bash
# 传完就删，保持本地干净；镜像本身可留着下次直接用
rm mall-images.tar.gz
```

## 后续更新代码后重新部署

改完代码，基础镜像（mysql/redis/minio）已在服务器上，**只需重新传业务镜像**这两个：

```bash
# 本机（在项目根目录）
docker buildx build --platform linux/amd64 -f Backend/Dockerfile  -t mall-admin:1.0    --load Backend
docker buildx build --platform linux/amd64 -f frontend/Dockerfile -t mall-frontend:1.0 --load frontend
docker save mall-admin:1.0 mall-frontend:1.0 | gzip > mall-images.tar.gz
scp mall-images.tar.gz root@ECS_IP:/opt/mall/

# 服务器
ssh root@ECS_IP 'cd /opt/mall && gunzip -c mall-images.tar.gz | docker load && docker compose -f docker-compose.prod.yml up -d'
```

`docker compose up -d` 只会重建镜像有变化的容器，MySQL/Redis/MinIO 的数据卷保留，数据不丢。

## 常见问题

- **`exec format error`**：镜像架构不对（构建成了 arm64）。回到步骤一，确认带了 `--platform linux/amd64`，重新构建并用步骤二校验。
- **`--load` 报不支持多平台**：`--load` 一次只能载入单一平台镜像；本手册每条命令只构建一个平台，正常。不要给一条命令加多个 `--platform`。
- **scp 慢**：3Mbps 带宽下几百 MB 的包需要几分钟到十几分钟，属正常；务必用 gzip 压缩后再传。
- **服务器磁盘不够 load**：`docker system prune -f` 清理旧的悬空镜像后重试。含 4 个镜像的包解压后占用约 1~1.5GB，确保 `/opt/mall` 所在磁盘有足够空间。
- **基础镜像 tag 对不上又联网拉**：`docker pull` 时的 tag 必须和 `docker-compose.prod.yml` 里的完全一致（`redis:7-alpine`、`minio/minio:latest`），否则服务器 `up` 时找不到本地镜像会尝试联网拉取。
- **后端连不上 MySQL**：本方案后端连的是服务器已有的 MySQL（`.env` 的 `DB_HOST=111.228.13.106`）。确认该 MySQL 正在运行、`mall` 库表存在（步骤五补）、且 root 密码与 `.env` 的 `DB_PASSWORD` 一致；京东云安全组需放行 3306（本地开发能连说明已放行）。
