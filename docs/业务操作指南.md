# mall 电商后台业务操作指南

> 面向运营 / 客服 / 商品 / 活动岗位，讲清「在后台哪一步做什么、字段怎么填、状态怎么流转」。
> 技术架构见 [ARCHITECTURE.md](./ARCHITECTURE.md)，接口明细见 [apis/API_DOC.md](./apis/API_DOC.md)。

---

## 1. 登录与界面导航

| 项目 | 说明 |
|------|------|
| 登录入口 | 后台前端地址 `/login` |
| 账号 | 管理员账号（演示环境：`admin` / `123456`） |
| 登录态 | 登录后颁发 Token 并本地保存；Token 失效会自动跳回登录页，重新登录即可 |

界面常用能力：

- **多标签页**：打开过的页面以标签驻留在顶部，可单独关闭。
- **全局搜索**：`⌘K` / `Ctrl+K` 唤起，输入页面名直达。
- **锁屏**：离开工位时锁定界面，解锁后回到原页面。
- **主题**：右上角可切换浅色 / 深色 / 跟随系统，并有 12 种主题色。

侧边栏共四条业务主线：**商品（PMS）/ 订单（OMS）/ 营销（SMS）/ 权限（UMS）**。

## 2. 新店开张：数据准备顺序

商品数据有依赖关系，**必须按下面顺序建**，否则新建商品时选不到品牌和分类：

```
① 品牌管理  →  ② 商品分类（一级 + 二级）  →  ③ 商品类型（属性/参数）
          →  ④ 商品列表（录入商品并上架）
          →  ⑤ 营销：首页广告、推荐位、优惠券、秒杀
          →  ⑥ 权限：按岗位建角色、开账号
```

> 说明：新建商品时，**商品分类下拉只显示二级分类**，所以一级分类下必须先建好二级分类。

## 3. 商品管理（PMS）

### 3.1 品牌管理 `商品 → 品牌管理`

- **新增**：点「添加品牌」，填写品牌名称、品牌首字母、排序、品牌 Logo、品牌大图、品牌故事；两个开关为「是否显示」（默认开）和「品牌制造商」（默认关）。
- **列表操作**：
  - 「品牌制造商」「是否显示」两列是开关，点一下立即生效，无需保存。
  - 搜索支持品牌名称 + 显示状态。
  - 支持勾选后「批量删除」。
- **相关商品数** 列可用来判断该品牌能否删除——有商品挂着的品牌不要随意删。

### 3.2 商品分类 `商品 → 商品分类`

- 分类只有**两级**：一级（level=一级）与其下的二级。
- 默认进来看到的是一级分类列表，点一级分类行的「查看下级」进入它的二级分类，点「返回上级」回到一级。
- **新增规则**：在一级列表点「添加分类」建的是一级分类；进入某个一级分类的下级列表后再点「添加分类」，建的是它的二级分类。
- 字段：分类名称（必填）、数量单位（如「件」「盒」）、分类图标、排序。
- 列表上的两个开关：
  - **导航栏**：是否出现在商城前台的导航入口。
  - **显示**：是否对用户可见。关掉等于前台隐藏该分类。

### 3.3 商品类型（属性 / 参数模板）`商品 → 商品类型`

用来沉淀「这类商品该填哪些规格和参数」的模板。

1. 点「添加属性分类」建一个类型（如「手机」「服装」）。
2. 在该行点「设置」进入详情页，页内有两个页签：
   - **商品属性**：影响下单选择的规格（如颜色、尺码）。
   - **商品参数**：仅做展示的参数（如屏幕尺寸、材质）。
3. 新增属性/参数时填：
   - 名称（必填）
   - 是否可选：`唯一` / `单选` / `多选`
   - 录入方式：`手工录入` / `从列表选取`
   - 可选值：多个值用**英文逗号**分隔（录入方式选「从列表选取」时必填）
   - 排序
4. 列表上的「属性数量 / 参数数量」即该类型下已配置的条数。

### 3.4 商品列表 `商品 → 商品列表`

**查询条件**：商品名称或货号、商品分类、上架状态、审核状态。

**行内开关**（点击即生效）：

| 列 | 含义 |
|----|------|
| 新品 | 是否打「新品」标 |
| 推荐 | 是否进推荐池 |
| 上架 | 是否对用户可售（下架后前台不可见） |

**批量操作**（先勾选左侧复选框，再点按钮）：批量上架、批量下架、批量审核、设为新品、设为推荐、批量删除。未勾选会提示「请先选择商品」。

**审核状态**：`未审核` / `审核通过`。走审核流程的店铺，商品需「批量审核」通过后再上架。

**新增 / 编辑商品**：点「添加商品」或行内「编辑」，进入四步向导（「下一步」切换步骤，最后一步才出现「提交」）：

| 步骤 | 填写内容 |
|------|----------|
| ① 填写商品信息 | 商品名称（必填）、货号、副标题、品牌、商品分类、商品图片、商品详情 |
| ② 填写商品促销 | 市场价、销售价格（必填）、库存、排序、上架 / 新品 / 推荐三个开关 |
| ③ 填写商品属性 | 当前版本为占位，暂不录入 |
| ④ 选择商品关联 | 当前版本为占位，暂不录入 |

> 注意：步骤 ③④ 尚未实现录入，SKU 规格与关联商品暂时无法在后台维护；列表里的「查看 SKU」按钮当前也无响应。

## 4. 订单管理（OMS）

### 4.1 订单状态

| 状态 | 含义 | 运营动作 |
|------|------|----------|
| 待付款 | 用户已下单未支付 | 超时未付自动关闭；也可手动「关闭」 |
| 待发货 | 已支付待出库 | 出库后点「发货」 |
| 已发货 | 已交付物流 | 等用户确认，或到期自动确认收货 |
| 已完成 | 交易结束 | 可进入售后流程 |
| 已关闭 | 已取消 / 已关闭 | 终态 |
| 无效订单 | 异常订单 | 终态 |

### 4.2 订单列表 `订单 → 订单列表`

- **查询**：订单编号、收货人、订单状态、订单分类（正常订单 / 秒杀订单）、提交时间区间；「重置」清空全部条件。
- **行内操作**：详情、关闭、发货、删除。
- **批量操作**：批量发货、批量关闭、批量删除（会弹二次确认，显示条数）。

> ⚠️ 当前版本「发货」是一键发货：物流公司固定写为**顺丰速运**，运单号为空。若业务上需要真实运单号，请先走线下物流系统，或联系开发补充发货弹窗。

### 4.3 订单详情 `列表 → 详情`

页面分块展示：订单信息、收货人信息、商品清单（含 SKU、规格、单价、数量）、费用信息（商品总额 / 应付 / 运费 / 优惠 / 优惠券抵扣 / 积分抵扣）、操作记录（时间、状态、操作说明、操作人）。

顶部三个可改项：

| 按钮 | 可改字段 | 典型场景 |
|------|----------|----------|
| 修改收货人 | 收货人、联系电话、详细地址 | 用户发货前要求改地址 |
| 修改费用 | 运费、优惠金额 | 补运费差价、临时让利 |
| 备注 | 订单备注 | 记录客服沟通结论 |

所有改动都会落到「操作记录」，便于追溯。

### 4.4 退货申请处理 `订单 → 退货申请处理`

状态流转：

```
待处理 ──确认退货──► 退货中 ──完成退货──► 已完成
   └────拒绝退货────► 已拒绝
```

- **查询**：收货人、申请状态、处理时间。
- 点「查看详情」进入处理页，页面展示申请信息、退货人信息、退货商品。
- 按钮按状态出现：
  - `待处理`：「确认退货」/「拒绝退货」
  - `退货中`：「完成退货」
  - `已完成` / `已拒绝`：无操作按钮（终态）
- 每次操作都会弹框要求填**处理备注**，备注会记录在案，请写清判定理由（如「已收到退回商品，外包装完好」）。

### 4.5 退货原因设置 `订单 → 退货原因设置`

维护用户申请售后时可选的原因列表。

- 字段：退货类型（必填）、排序、启用状态。
- 支持行内开关启用/禁用、批量启用、批量禁用、批量删除。
- **建议禁用而非删除**：历史申请仍引用原因文案。

### 4.6 订单设置 `订单 → 订单设置`

全局超时规则，保存后对新订单生效：

| 字段 | 含义 | 参考值 |
|------|------|--------|
| 秒杀订单超时关闭时间(分) | 秒杀下单后多久未付自动关单 | 10～30 |
| 正常订单超时时间(分) | 普通订单下单后多久未付自动关单 | 60～120 |
| 发货后自动确认收货时间(天) | 发货后多少天自动确认收货 | 7～15 |
| 自动完成交易时间(天) | 确认收货后多少天自动完成 | 7 |
| 订单完成后多少天不能申请售后 | 超过该天数售后入口关闭 | 7～15 |

> 「重置」按钮是**重新拉取已保存的值**，不是清零。

## 5. 营销管理（SMS）

### 5.1 秒杀：三步配置

秒杀由「活动 → 时段 → 商品」三张表组合，**必须按顺序配**：

**① 秒杀活动列表** `营销 → 秒杀活动列表`
- 点「添加」，填活动名称 + 活动日期区间（按天）。
- 列表上「上下线状态」开关控制活动是否生效。
- 行内「秒杀时段」「秒杀商品」可直接跳到对应配置页。

**② 秒杀时段** `营销 → 秒杀时段`
- 点「添加秒杀时段」，填场次名称（如「零点场」「上午场」）+ 时段（时:分:秒，分钟按 15 分步进）。
- 场次是**全局复用**的，不属于某个活动；开关控制是否启用。

**③ 秒杀商品** `营销 → 秒杀商品`
- 页面顶部**先选「秒杀活动」再选「场次」**，两者都选中后「添加秒杀商品」按钮才可用（否则灰置）。
- 添加时：在「选择商品」下拉里按商品名称 / 货号搜索并选中，然后填秒杀价、秒杀库存、限购数量、排序。
- 列表会显示原价与秒杀价对照，便于复核折扣。

> 常见问题：秒杀前台不显示 → 依次检查「活动是否上线」「活动日期是否覆盖今天」「场次是否启用」「该活动+场次下是否关联了商品」。

### 5.2 优惠券 `营销 → 优惠券列表`

- 列表字段：名称、类型、面值、发行量、已领取、已使用、有效期。「已领取 / 已使用」用于评估活动效果。
- 新增/编辑字段：

| 字段 | 说明 |
|------|------|
| 优惠券名称 | 必填 |
| 优惠券类型 | 全场赠券 / 会员赠券 / 购物赠券 / 注册赠券 |
| 面值 | 抵扣金额（元） |
| 发行数量 | 总发行量 |
| 每人限领 | 单个用户最多领取张数（≥1） |
| 最低消费 | 门槛金额（元），0 表示无门槛 |
| 有效期 | 起止时间（可精确到时分秒） |
| 使用范围 | 全部 / 指定分类 / 指定商品 |
| 优惠券说明 | 展示给用户的使用说明 |

> 注意：「使用范围」选了「指定分类 / 指定商品」后，具体的分类和商品范围当前后台页面还不能选，需开发补充；列表里的「查看领取详情」按钮暂无响应。

### 5.3 首页运营位

四个推荐位用法完全一致（`营销 → 品牌推荐 / 新品推荐 / 人气推荐 / 专题推荐`）：

- 按名称 + 推荐状态搜索。
- 行内开关切换「推荐 / 取消推荐」；勾选后可「批量推荐」「批量取消」「批量删除」。
- 排序列数值越小越靠前（具体由前台渲染规则决定）。

> 当前页面只能管理**已有的推荐记录**（改状态、改顺序、删除），新增推荐项需由开发或数据侧写入。

### 5.4 广告列表 `营销 → 广告列表`

- 新增/编辑字段：广告名称（必填）、广告位置（`PC首页轮播` / `APP首页轮播`）、投放时间区间（必填）、上线/下线、排序（必填）、广告图片（必填）、链接地址、备注。
- 列表可直接开关「上下线状态」，并按广告名称搜索。
- **投放三要素**：状态为上线 + 当前时间在投放区间内 + 位置选对，三者缺一前台都不展示。

## 6. 权限管理（UMS）

推荐配置顺序：**菜单 / 资源 → 角色 → 给角色分配 → 开用户账号**。

### 6.1 菜单列表 `权限 → 菜单列表`

- 两级结构，和商品分类一样用「查看下级 / 返回上级」浏览。
- 字段：菜单名称（必填）、前端名称、前端图标、级别、排序。
- 「是否显示」开关 = 该菜单在侧边栏是否可见。

### 6.2 资源列表 `权限 → 资源列表`

- 资源即**接口级权限**，字段：资源名（必填）、资源路径（必填）、描述、资源分类。
- 支持按资源分类 + 资源名搜索。

### 6.3 角色列表 `权限 → 角色列表`

- 新增/编辑：名称（必填）、描述、排序。
- 「状态」开关控制角色启用与否；「用户数」显示挂在该角色下的账号数。
- 行内「分配菜单」「分配资源」：在弹框的多选框里选择后点确定即生效。

> ⚠️ 分配弹框里的下拉选项来自「该角色当前已有的菜单/资源」，不是全量清单。因此它适合**做减法**（移除已有权限）；要新增该角色还没有的权限，目前需开发侧补全量选项。分配前请先确认提交内容，避免误提交空选导致权限被清空。

### 6.4 用户列表 `权限 → 用户列表`

- 按用户名搜索，列表显示用户名、昵称、邮箱、备注、状态、添加时间、最后登录。
- 「状态」开关 = 启用 / 禁用账号。离职或临时冻结用这个，不要直接删。
- 「删除」会移除账号，不可恢复。

> ⚠️ 当前版本「修改」按钮无响应；「分配角色」弹框虽能选择角色，但**提交后不会真正保存**（仅前端提示成功）。新开账号与角色绑定暂需走后端处理，请勿以此页面结果为准。

## 7. 用户侧（H5 商城）对应关系

后台配置最终体现在 H5 商城上，排查「前台看不到」类问题时按这个对应关系找：

| H5 页面 | 对应后台配置 |
|---------|--------------|
| 首页 | 广告列表（轮播）、品牌/新品/人气/专题推荐 |
| 分类页 | 商品分类（导航栏、显示开关） |
| 商品详情 | 商品列表（上架、审核状态）、品牌管理、商品类型 |
| 购物车 / 下单 / 支付 | 订单设置（超时规则）、优惠券 |
| 秒杀 | 秒杀活动 + 秒杀时段 + 秒杀商品 |
| 我的订单 | 订单列表（状态、发货） |
| 申请售后 / 售后列表 | 退货原因设置 → 退货申请处理 |
| 评价 | 订单完成后由用户发起，后台可查看 |

## 8. 日常运营 SOP

**每日**
1. 订单列表筛「待发货」→ 核对后发货。
2. 退货申请处理筛「待处理」→ 当日内给出结论并写处理备注。
3. 广告 / 秒杀活动检查是否有当天到期的，到期及时下线。

**每周**
1. 优惠券列表看「已领取 / 已使用 / 发行量」，评估下一轮活动力度。
2. 商品列表筛「未审核」，清理积压。
3. 首页推荐位（新品 / 人气 / 专题）轮换一批。

**大促前**
1. 商品：价格、库存、上架状态全量复核。
2. 秒杀：活动上线 + 场次启用 + 商品关联（含秒杀价、秒杀库存、限购）三项逐一确认。
3. 优惠券：有效期覆盖活动全程，门槛与面值复核。
4. 广告：Banner 图、链接地址、投放时间、上线状态确认。
5. 订单设置：按大促节奏调短「秒杀订单超时关闭时间」。

## 10. 当前版本的功能缺口（运营需知）

以下为后台页面尚未实现的部分，遇到时请走线下流程或提需求，不要误判为故障：

| 位置 | 缺口 |
|------|------|
| 商品 → 添加/编辑商品 | 第 ③ 步「商品属性」、第 ④ 步「选择商品关联」为占位，无法录入 |
