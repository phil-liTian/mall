# 部署到京东云服务器（前后端整套）

> 目标：把 mall（React 前端 + Spring Boot 后端 + Redis + MinIO）部署到京东云轻量云主机 `111.228.13.106`，通过 `http://mall.starchase.xyz` 访问。
> MySQL 复用服务器已有的（`111.228.13.106:3306`），不容器化。
> 本机是 Mac(arm64)，服务器是 amd64，需交叉编译。

---

## 一、整体思路

```
公网 → 宿主机 nginx(80，按域名分流) → 容器 nginx(127.0.0.1:8080) → mall-admin:8082
                                                              ↘ minio:9000 (/mall-files)
```

- 服务器上**已有宿主 nginx** 在服务其他站点（starchase.xyz 等），占用了 80/443。
- 所以本项目的容器 nginx **不抢占公网 80**，只监听 `127.0.0.1:8080`，由宿主 nginx 用子域名 `mall.starchase.xyz` 反代过来，与现有站点共存。
- 镜像在本机交叉编译成 amd64，打包成 tar 传到服务器 `docker load`，服务器全程不联网拉镜像。

---

## 二、一次性前置（本机，装过跳过）

本机 Docker 运行时是 Colima，buildx 需手动装：

```bash
mkdir -p ~/.docker/cli-plugins
curl -fSL https://github.com/docker/buildx/releases/download/v0.19.3/buildx-v0.19.3.darwin-arm64 \
  -o ~/.docker/cli-plugins/docker-buildx
chmod +x ~/.docker/cli-plugins/docker-buildx
docker run --privileged --rm tonistiigi/binfmt --install amd64
docker buildx create --name mallbuilder --driver docker-container --use
docker buildx inspect --bootstrap
```

**Colima 内存要给够**（vite 构建吃内存，默认 2G 会 OOM）：

```bash
colima stop
colima start --cpu 4 --memory 8
```

## 三、镜像源（绕开 Docker Hub 污染）

国内直连 `registry-1.docker.io` 会 DNS 污染 / TLS 报错，本项目基础镜像已改为走国内镜像源：

| 镜像 | 来源 |
|---|---|
| `maven:3.8-eclipse-temurin-8`、`eclipse-temurin:8-jre` | `docker.m.daocloud.io/library/...`（写死在 `Backend/Dockerfile`） |
| `node:20-alpine`、`nginx:1.27-alpine` | `docker.m.daocloud.io/library/...`（写死在 `frontend/Dockerfile`） |
| `redis:7-alpine` | `docker.m.daocloud.io/library/redis:7-alpine` |
| `minio/minio:latest` | `quay.m.daocloud.io/minio/minio:latest`（daocloud、1ms、xuanyuan 均屏蔽了 minio 命名空间，只有 quay 代理可用） |

`deploy-fullstack.sh` 用 buildx 把 redis/minio 重导出为 amd64 单平台专用镜像（`mall-redis:1.0`、`mall-minio:1.0`），避免本机已有的 arm64 同名镜像干扰，服务器 load 后再改名回 compose 认的名字。

## 四、部署（本机一条命令）

在项目根目录 `/Users/litian.phil/phil/java/mall`：

```bash
bash deploy-fullstack.sh
```

脚本自动完成 7 步：
1. 检查 `.env`
2. 检查 / 创建 buildx builder
3. 交叉构建后端 amd64 镜像 `mall-admin:1.0`
4. 交叉构建前端 amd64 镜像 `mall-frontend:1.0`
5. buildx 重导出 redis/minio 为 amd64 → 校验四个镜像都是 amd64 → 打包 `mall-images.tar.gz`
6. scp 上传镜像包 + `docker-compose.prod.yml` + `.env` 到 `/opt/mall`
7. **自动 ssh 到服务器**：装 docker（若无）→ 建 2G swap → `docker load` → 改名 → `docker compose up -d`

> 无需手动登录服务器操作，第 7 步全自动。

## 五、服务器端 nginx 反代（首次一次性）

因为宿主 nginx 已占 80，需给它加一段反代把子域名转到容器。SSH 到服务器：

```bash
cat > /etc/nginx/conf.d/mall.conf <<'EOF'
server {
    listen 80;
    server_name mall.starchase.xyz;

    client_max_body_size 12m;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
EOF

nginx -t          # 必须 test is successful
systemctl reload nginx
```

> `[warn] conflicting server name "starchase.xyz"` 是现有配置的重复告警，与本项目 `mall.starchase.xyz` 无关，可忽略。

## 八、验证

```bash
# ① 服务器本机：容器 nginx 通不通
ssh root@111.228.13.106 'curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080'   # 期望 200

# ② 服务器本机：宿主 nginx 反代通不通
ssh root@111.228.13.106 'curl -s -o /dev/null -w "%{http_code}\n" -H "Host: mall.starchase.xyz" http://127.0.0.1'  # 期望 200

# ③ 公网访问
浏览器打开 http://mall.starchase.xyz
```

后端启动约 60~90 秒（连 MySQL、初始化）。看日志：

```bash
ssh root@111.228.13.106 'cd /opt/mall && docker compose -f docker-compose.prod.yml logs -f mall-admin'
# 出现 "Started MallAdminApplication" 即就绪
```

## 九、更新代码后重新部署

改完代码，只需本机重跑：

```bash
bash deploy-fullstack.sh
```

基础镜像走缓存，主要是重编译前后端 + 重传。若服务器报容器名冲突（旧容器占用）：

```bash
ssh root@111.228.13.106 'cd /opt/mall && docker compose -f docker-compose.prod.yml down'
# 再重跑 deploy-fullstack.sh；数据卷（redis-data/minio-data）默认保留，数据不丢
```

## 十、关键文件

| 文件 | 作用 |
|---|---|
| `deploy-fullstack.sh` | 一键交叉编译 + 打包 + 上传 + 服务器部署 |
| `Backend/docker-compose.prod.yml` | 生产编排（redis + minio + mall-admin + nginx:8080） |

| `/etc/nginx/conf.d/mall.conf`（服务器上） | 宿主 nginx 反代子域名到容器 |

---

## 十一、MinIO 访问说明

- **文件公网地址**：`http://mall.starchase.xyz/mall-files/mall/<文件名>`（宿主 nginx → 容器 nginx `/mall-files/` → `minio:9000`，只读）。由 `.env` 的 `MINIO_PUBLIC_URL` 决定。
- **管理控制台(9001)**：生产未映射到公网，出于安全不暴露。需要时可通过 SSH 隧道临时访问。

---

## 十二、以后上 HTTPS（可选）

有 `*.starchase.xyz` 泛域名证书或单独给 `mall.starchase.xyz` 签发后：

1. 证书放服务器（如 `/opt/mall/certs/`）。
2. 改 `/etc/nginx/conf.d/mall.conf`：加 `listen 443 ssl` + `ssl_certificate` 两行，80 段改成 301 跳转 443。
3. `.env` 的 `MINIO_PUBLIC_URL` 改成 `https://mall.starchase.xyz/mall-files`，重新部署。
4. `nginx -t && systemctl reload nginx`。

> 证书只加在**宿主 nginx**，容器 nginx 保持 HTTP 即可（内网流量）。
